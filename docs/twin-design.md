# 数字分身（twin）设计文档

> 状态：草案，边做边聊，细节逐步填充
> 日期：2026-08-16

## 1. 定位（一句话）

一个「我」的数字化身：通过 PTY 像人一样和 shell / 系统交互，带着我的工作原则干活。先做「实时陪伴型」，远期「全天候自主」。

## 2. 核心共识

- **分身 = 我的工作方法论的化身，不是 1:1 复刻**。保留「能把活干好」的习惯（严谨、先验证再交付、高内聚低耦合、遇岔路停下判断），剥离我的短处。
- **「像」发生在原则 / 决策层，不在按键 / 行为层**。优点必须守住，短处可以超越。
- **PTY 是分身的存在方式**（不是「测 phimint 界面」的手段）：分身坐在 shell 前面，读屏、敲命令。不管编码、连服务器、跑 phimint、执行命令，都是「通过 PTY 能做的事」。
- **先做到阶段 1（实时陪伴），理想是 3（全天候），不越级**。底层没夯实就停在底层夯。

## 3. 分阶段路线图

| 阶段 | 目标 | 到了没 |
|------|------|--------|
| **0 · 读屏（实时终端模拟器）** | fork 一个 shell，把 PTY 字节流实时还原成「屏幕文本快照」，真人也能 attach 看到同一屏 | 跑 `ls` / `vim` / `cargo build`（带颜色、光标移动），快照和真实终端一致 |
| **1 · 会看会打（最小闭环）** | LLM 循环接管 shell PTY：读屏 → 想 → 敲一条命令 → 读新屏 | 一句「把 phimint 跑起来」，能 `cd` + `cargo build` + 读出报错复述 |
| **2 · 实时陪伴（可干预）** | 真人实时看同一 PTY，随时打断 / 纠正 / 接管 | 干到一半说「不对，先 `git status`」，能停、能照办 |
| **3 · 人格注入（原则层像我）** | `working-principles` 变成决策护栏 | 丢一个需判断的任务，走法符合我的习惯 |
| **4 · 远眺（任务派发 → 全天候）** | 只标方向，不强求 | — |

## 4. 阶段 0 是地基（唯一要新造的）

- **唯一新造的能力 = 读屏**：把 PTY 吐回的字节流（含 ANSI 转义 + 光标移动）实时还原成「此刻屏幕长什么样」再喂给 LLM。
- 复用 `replay.rs` 的迷你 ANSI 终端模拟器，从「离线回放」升级成「实时 + 可驱动」。
- 其余全是已有积木：`pty.fork` 是手、phi-agent 的 LLM 循环是脑、`working-principles` 是人格。

## 5. 可复用资产

| 资产 | 用途 |
|------|------|
| `phi-agent`（agent 循环 / LLM） | 脑 |
| `pty.fork` 驱动（phimint 真机测试已在用） | 手 |
| `replay.rs` 迷你终端模拟器 | 读屏引擎 |
| `working-principles`（memory） | 人格 |
| `ai-terminal`（Python/pexpect 原型） | 思想借鉴，Rust 重写 + 升级 |
